The YOLO-MIT deps are easy to miss: without `lightning` the MIT engine dies at
`from yolo.model.yolo import create_model`, and because each arm is a separate process the
run keeps going and simply produces **no output for that model** — six tracebacks buried in
a log rather than one loud failure. Always `grep -c Traceback` the log before reading
results.

Add the cu128 torch line ONLY on a Blackwell (sm_120) pod — see
`blackwell-pod-torch-cu128` in memory. An RTX 4090 / 4000 Ada works on the stock
torch 2.4.1+cu124.

## Traps hit this session (all cost real time)

- **`pkill -f <script>.sh` matched the ssh command line carrying that same string** and
  killed the session before the relaunch ran — CLAUDE.md warns about exactly this. Put kill
  + relaunch in a script file and `setsid nohup` it.
- **`nohup … &` inside `ssh '…'` still holds the channel open** and the call hangs; add
  `>/dev/null 2>&1 </dev/null` and wrap in `bash -c`.
- **No `-u` on a nohup'd python job** means block-buffered output — a job that is running
  fine looks dead for ten minutes. Always `python3 -u`.
- **A heredoc inside `ssh '…'`** breaks on the first apostrophe in the prose (it closes the
  outer quote). Write the file locally and `scp` it.
- **Reading image headers off the volume is the bottleneck**, not compute: ~11 img/s for
  the holdout's 11,494 symlinks (>17 min for one census). Budget for it or parallelise.
- **`timeout` does not exist on macOS** — don't put it in local wrapper commands.

## Session 2 traps

- **This pod kills detached jobs.** `nohup`, `setsid nohup`, `</dev/null` — all of it. Every
  long job died the moment the ssh connection dropped, three times, with no traceback, no
  OOM (61 GB cgroup limit, 5.9 GB used, `memory.events` zero) and a healthy volume
  (632 MB/s write probe). The same command run in the foreground completed fine. **What
  works: hold the ssh session open from the client** —
  `ssh -o ServerAliveInterval=20 -o ServerAliveCountMax=2000 runpod 'bash script.sh'`
  launched with the Bash tool's `run_in_background`. The connection still drops eventually,
  so checkpoint long runs and make every step resumable.
- **A float target in an f-string names a directory `h96.0`, not `h96`** — and
  `run_ultralytics_labels.py` pointed at a non-existent directory reports
  `processed=0` and exits 0. `set -e` does not catch it. Five arms silently scored nothing.
  Fixed with `f"h{target:g}"`; **always check `processed=N` per dataset.**
- **Nested same-type quotes in an f-string are a syntax error on the pod's Python 3.11.**
  Write the script to a file and `scp` it rather than fighting quoting through ssh.
- **The per-height synth dirs had no `manifest.json`** (only the parent did), so anything
  pointed at one crashed. Each height dir is now self-describing.
